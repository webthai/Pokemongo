# RAID Pokemon Go Hub — Pokémon GO Dashboard

เว็บแดชบอร์ดหน้าเดียวที่รวม **บอสเรดปัจจุบัน**, **Community Day**, และ **โบนัสสภาพอากาศ** ของ Pokémon GO ไว้ในที่เดียว เป็น static site ล้วนๆ (HTML/CSS/JS) ไม่มี backend ไม่มีฐานข้อมูลของตัวเอง

## แหล่งข้อมูล

| ข้อมูล | มาจาก | อัปเดตบ่อยแค่ไหน |
|---|---|---|
| บอสเรดปัจจุบัน, Community Day / อีเวนต์ | [LeekDuck.com](https://leekduck.com) ผ่าน [ScrapedDuck](https://github.com/bigfoott/ScrapedDuck) | ทุกไม่กี่นาที (ScrapedDuck สแครปจาก LeekDuck โดยได้รับอนุญาต) |
| ตารางธาตุ (จุดอ่อน/จุดต้าน), โบนัสสภาพอากาศ | [PoGo API](https://pogoapi.net) | นานๆ ครั้ง (ข้อมูลกลไกเกม ไม่ใช่ข้อมูลรายวัน จึงไม่ต้องอัปเดตบ่อย) |

> **หมายเหตุสำคัญ:** เดิมทีเว็บนี้ใช้ pogoapi.net สำหรับข้อมูลบอสเรดด้วย แต่พบว่าข้อมูลไม่ตรงกับรอบปัจจุบันจริง (ยังมี Tier 2/4/6 ค้างอยู่ ทั้งที่เกมตอนนี้เหลือแค่ Tier 1/3/5/Mega) จึงเปลี่ยนมาใช้ **ScrapedDuck ซึ่งดึงข้อมูลจาก LeekDuck.com โดยตรง** แทน เพราะ LeekDuck เป็นแหล่งข้อมูลที่แม่นและไวที่สุดในวงการ Pokémon GO

## มีอะไรให้ดูบ้าง

- **บอสเรดปัจจุบัน** — แบ่งตาม Tier (1-Star, 3-Star, 5-Star, Mega — ตามที่มีจริงในเกม ไม่ใช่ตายตัว 6 tier แบบเดิม) แต่ละใบการ์ดโชว์ธาตุ, ช่วง CP ปกติ/ตอนอากาศบูสต์, สภาพอากาศที่บูสต์บอสตัวนั้น, และบอกว่ามีโอกาสเจอเชนี่ไหม
- **ค้นหาและกรอง** — พิมพ์ชื่อโปเกมอน หรือกดเลือกธาตุ (เลือกได้หลายธาตุ) พอมีการค้นหา/เลือกธาตุ ระบบจะค้นข้ามทุก Tier ให้อัตโนมัติ พร้อมโชว์ป้าย Tier บนการ์ดแต่ละใบ กด "ล้างตัวกรอง" เพื่อกลับไปดูแบบแยก Tier ตามปกติ
- **กดที่การ์ดบอสตัวไหนก็ได้** เพื่อเปิดหน้าต่างรายละเอียด บอกว่า:
  - ใช้ธาตุอะไรตีแล้วโดนแรงขึ้น (จุดอ่อน) — คำนวณรวมธาตุคู่ให้ถูกต้องแบบเดียวกับในเกม (เช่น บอสธาตุมังกร+บิน จะโดนน้ำแข็งแรงเป็นพิเศษ เพราะน้ำแข็งแรงต่อทั้งมังกรและบิน)
  - บอสต้านธาตุอะไรได้ (โจมตีแล้วไม่ค่อยเจ็บ)
  - มีธาตุไหนที่ไม่โดนเลยไหม (ภูมิคุ้มกัน 0×)
- **Community Day** — ชื่ออีเวนต์, ช่วงวันที่ (แปลงเป็นเวลาไทยให้แล้ว), โปเกมอนที่ออกเยอะเป็นพิเศษ, โบนัสของวันนั้น, เชนี่ที่มีโอกาสเจอ พร้อมลิงก์ไปดูรายละเอียดเต็มบน LeekDuck
- **โบนัสสภาพอากาศ** — ตารางอ้างอิงว่าอากาศแบบไหนบูสต์ธาตุอะไรบ้าง
- นาฬิกาบนหัวเว็บเป็นเวลาไทย (Asia/Bangkok, UTC+7) เสมอ

## ทำไมถึงไม่ดึงข้อมูลจาก Campfire

Campfire (แอปโซเชียลของ Niantic ที่โชว์เรดใกล้ตัว) **ไม่มี public API** ให้บุคคลภายนอกดึงข้อมูลได้ มันมี API ภายในของ Niantic เอง (`niantic-social-api.nianticlabs.com`) แต่ต้องผูกกับบัญชีที่ล็อกอินจริงผ่าน session token ส่วนตัว การจะดึงข้อมูลจากมันจึงต้องปลอมตัวเป็นแอปที่ใช้บัญชีจริงล็อกอินอยู่ตลอด ซึ่งเข้าข่ายเข้าถึงระบบโดยไม่ได้รับอนุญาตและเสี่ยงบัญชีโดนแบน โปรเจกต์นี้จึงไม่รองรับ Campfire และใช้เฉพาะแหล่งข้อมูลสาธารณะที่เปิดให้ใช้ฟรีอย่างถูกต้อง (LeekDuck ผ่าน ScrapedDuck, pogoapi.net) เท่านั้น

## ทำไมถึงไม่มีแผนที่

ตำแหน่งยิม/Power Spot สดๆ ในเกม (ว่าตอนนี้มีเรดที่ไหนบ้าง) **ไม่มี API สาธารณะที่ถูกกฎหมาย** ให้ดึงได้ Niantic ไม่เปิดข้อมูลตำแหน่งเรียลไทม์นี้ เว็บ "แผนที่เรดสด" ที่เห็นตามอินเทอร์เน็ตส่วนใหญ่ได้ข้อมูลมาจากบัญชีที่ปลอมตำแหน่ง (location spoofing) จำนวนมากทำงานตลอดเวลา ซึ่งผิดกฎการใช้งานของเกม โปรเจกต์นี้จึงตั้งใจไม่ทำฟีเจอร์แผนที่ เพื่อไม่ให้ต้องพึ่งพาข้อมูลจากแหล่งที่ผิดกฎ

## ทำไมถึงไม่ต้องตั้งค่าอะไรเลย

เพราะเว็บนี้ไม่มีระบบล็อกอิน ไม่มีฐานข้อมูลของตัวเอง และไม่ต้องมี API key — มันแค่ยิง `fetch()` ไปที่ API สาธารณะตรงๆ จากเบราว์เซอร์ของผู้ใช้ทุกครั้งที่เปิดหน้าเว็บ ทำให้ deploy ขึ้น GitHub Pages ได้เลยแบบไม่ต้องแก้โค้ดอะไรก่อน

## ไฟล์ในโปรเจกต์

| ไฟล์ | หน้าที่ |
|---|---|
| `index.html` | โครงหน้าเว็บทั้งหมด |
| `style.css` | ธีมและ layout (โทนมืด, ธีม "เทอร์มินัลล่าเรด") |
| `app.js` | ดึงข้อมูลจาก API, render การ์ดต่างๆ, นาฬิกา, ปุ่มรีเฟรช, ตัวกรอง |
| `README.md` | ไฟล์นี้ |

## วิธี Deploy ขึ้น GitHub Pages (ฟรี)

### ขั้นตอนที่ 1 — สร้าง Repository
1. เข้า [github.com](https://github.com) แล้วกด **New repository**
2. ตั้งชื่อ เช่น `pogo-raid-dashboard`
3. เลือก **Public**
4. กด **Create repository**

### ขั้นตอนที่ 2 — อัปโหลดไฟล์
1. ในหน้า repository ที่เพิ่งสร้าง กด **Add file → Upload files**
2. ลากไฟล์ทั้ง 3 ไฟล์เข้าไป: `index.html`, `style.css`, `app.js` (จะอัปโหลด `README.md` ด้วยก็ได้)
3. กด **Commit changes**

### ขั้นตอนที่ 3 — เปิดใช้งาน GitHub Pages
1. ไปที่แท็บ **Settings** ของ repository
2. เมนูซ้ายเลือก **Pages**
3. ใต้หัวข้อ **Build and deployment** → **Source** เลือก **Deploy from a branch**
4. **Branch** เลือก `main` และโฟลเดอร์เลือก `/ (root)` แล้วกด **Save**
5. รอประมาณ 1-2 นาที แล้วรีเฟรชหน้า Settings → Pages อีกครั้ง จะเห็นลิงก์ประมาณ:
   ```
   https://<ชื่อผู้ใช้ของคุณ>.github.io/pogo-raid-dashboard/
   ```
6. เข้าลิงก์นั้นได้เลย เว็บพร้อมใช้งานทันที

> ไม่ต้องตั้งค่า Apps Script, ไม่ต้องมี Google Sheet, ไม่ต้อง deploy อะไรเพิ่มอีก เพราะเว็บนี้ไม่มี backend ของตัวเอง

## การแก้ไข/ปรับแต่งภายหลัง

- อยากเปลี่ยนสีธีม → แก้ตัวแปรใน `:root { ... }` ที่บรรทัดต้นๆ ของ `style.css`
- อยากเปลี่ยนแหล่งข้อมูล → แก้ค่า `RAIDS_URL`, `EVENTS_URL`, `POGOAPI_BASE` ที่ต้นไฟล์ `app.js`
- ทุกครั้งที่แก้ไฟล์แล้วอัปโหลดใหม่ (หรือ push ผ่าน git) GitHub Pages จะอัปเดตเว็บให้อัตโนมัติภายในไม่กี่นาที ไม่ต้อง deploy ซ้ำแบบ Apps Script

## เงื่อนไขการใช้ข้อมูล (สำคัญถ้าจะแก้ไข/แจกจ่ายต่อ)

ScrapedDuck อนุญาตให้ใช้ข้อมูลฟรี แต่มีเงื่อนไข:
- ห้ามเอาไปทำเป็นของที่ต้องจ่ายเงินถึงจะใช้ได้ (ห้าม paywall)
- ห้ามหารายได้จากโฆษณาในแอปที่ใช้ข้อมูลนี้
- ต้องให้เครดิต ScrapedDuck และ **LeekDuck.com** เสมอ (เว็บนี้ใส่เครดิตไว้ที่ท้ายหน้าแล้ว — ถ้าแก้ไข อย่าลบส่วนนี้ทิ้ง)

## ข้อจำกัดที่ควรรู้

- ข้อมูลทั้งหมดมาจากโปรเจกต์ชุมชน ไม่ใช่ช่องทางทางการของ Niantic — ความแม่นยำขึ้นกับผู้ดูแลแต่ละโปรเจกต์ แม้ ScrapedDuck จะอัปเดตบ่อยและตรงกับ LeekDuck เกือบเรียลไทม์ ก็ยังมีโอกาสหน่วงได้บ้างในบางช่วง (เช่น ตอนที่ Niantic เพิ่งเปลี่ยนรอบเรด)
- ถ้า ScrapedDuck หรือ PoGo API ล่มหรือเปลี่ยนโครงสร้างข้อมูล เว็บนี้อาจโหลดไม่ขึ้นชั่วคราว — กดปุ่มรีเฟรช (มุมขวาบน) เพื่อลองใหม่ได้
- ฟีเจอร์ "โชว์รอบก่อนหน้า" ถูกเอาออกแล้ว เพราะแหล่งข้อมูลใหม่ (ScrapedDuck) มีเฉพาะข้อมูลรอบปัจจุบัน ไม่มีประวัติย้อนหลัง
- ไม่มีแผง Max Battles (ไดนาแมค) เพราะทดสอบแล้วโหลดไม่เสถียรพอในบางสภาพแวดล้อม จึงตัดออกเพื่อความเสถียรของส่วนที่เหลือ
